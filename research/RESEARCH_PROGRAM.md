# Olympus Research Program

This document is the claim boundary for the research material stored in this
workspace. Executable code, a passing smoke test, and a scientific result are
different states and must not be used interchangeably.

## 1. Pantheon: active empirical program

**Question:** Can canonical execution packages detect disagreements and
replication failures that pairwise or numeric-only comparisons miss?

**Completed evidence:** A synthetic controlled benchmark, a small WDBC public
case, and an external agent study whose agents failed the frozen capability
floor. The external study is a valid negative result but cannot estimate false
consensus among capable agents.

**Paper basis:** Methods, reproducibility, and research-software artifact. The
current package supports a bounded preprint or artifact submission. Broad
claims about autonomous research require a confirmatory capable-agent study,
natural failure cases, independent implementations, and blinded human review.

## 2. Model Foundry: active software program

**Question:** Can local model experiments be made hash-bound, reproducible, and
fail-closed from dataset registration through promotion and export?

**Completed evidence:** The character-bigram lifecycle and tiny-transformer
training/evaluation machinery exercise real code paths. The tiny transformer
improved held-out loss but failed exact task and tool metrics; no Hermes model
is promoted. The packing smoke produced no measured benefit.

**Paper basis:** Research-software or systems artifact after source provenance,
locked clean-run reproduction, and comparisons with existing tooling. It does
not currently support a novel language-model claim.

## 3. LabOS: engineering incubation

LabOS discovers project manifests, records runs, and generates local reports.
Its current reports include projects outside this repository and are not
evidence for Olympus research claims. It should become either a separately
versioned research-operations tool or an explicitly scoped Foundry component.
A paper would require a real multi-project deployment study or user evaluation.

## 4. Cognitive primitives: demonstrations only

Interpretive branching, retrodiction, JEPA-inspired prediction, learned
transforms, rule-based representation selection, dependency-aware specialist
scheduling, and Forge graph compilation are deterministic or synthetic
engineering demonstrations. They have no frozen external benchmark, competitive
baseline, ablation matrix, or independent replication. They form one demo
collection, not separate paper claims.

## 5. Family reference implementations: hypotheses remain parked

The shared substrate and Hermes, Prometheus, Perseus, Olympus-Atlas, Kronos,
and Aion roles now have executable reference components. They establish typed
interfaces, selected deterministic validation/gating paths, and differentiable
training paths. Hermes and Prometheus have partial shared-workspace integration;
the complete six-role runtime does not exist. The families still have no
qualifying datasets, checkpoints, comparative evaluations, or promoted
artifacts. The research hypotheses remain inactive until frozen admission,
baseline, evaluation, and promotion protocols are satisfied.

## Priority order

1. Run the Pantheon capable-agent confirmatory protocol.
2. Make Foundry a reproducible, externally compared software artifact.
3. Split or explicitly integrate LabOS based on actual users and ownership.
4. Keep cognitive primitives only as honestly named educational fixtures.
5. Do not confuse executable reference code with evidence for model-family
   branding or capability.

Portfolio and outreach files under `docs/` that describe sibling projects are
external planning records. Their claims are not verified by this repository and
must not be cited as Olympus results.
